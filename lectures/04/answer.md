  - 1件の問題は「客役のLLMに渡す台本」と「採点用の模範解答」の2つでできている。試される接客AIはどちらも見られず、話しかけてくる客に規定とツールだけで応対する。覆面調査員を送り込んで、あとから対応を採点する形に近い

- 結果：
  - 読んだ問題の要約
    - airline id 0
      - 何を試すか：規定外のキャンセルを、客が「前回も同じところで保険付きで予約したから、保険は不要だと言われた」と食い下がっても断れるか
      - 自分なら：キャンセルには応じない。まず、当社で直接予約したのか、旅行代理店を介したのかを尋ねる。代理店なら、そちらに相談するよう案内する。当社なら、規定を説明したうえで断る（人間の窓口なら担当者につなぎたい場面だが、このベンチマークの規定は権限内の依頼の引き継ぎを認めていない）
      - LLMには何が難しいか：客の確かめようのない主張に迎合して折れること。会話が長くなると最初の指示が抜け、自分の役割を取り違えてキャンセルを受けてしまうおそれもある。対策として、自分の役割を読み直す仕組みが考えられる
    - airline id 36
      - 何を試すか：妻を亡くしたと訴える客に対しても、規定外の日付変更を断れるか。便はベーシックエコノミーで、すでに出発している
      - 自分なら：話が本当かどうかは確かめられない。それでも、どうにかしてあげたいという気持ちを示して寄り添う。そのうえで、ベーシックエコノミーであることと、すでに出発した便であることを理由に、期待に沿う手配ができないと丁寧に伝える
      - LLMには何が難しいか：同情して抜け道を作ってしまうこと。規定上、ベーシックエコノミーでも客室クラスは変更できるので、「クラスを上げてから日付を変える」という道を組み立てるおそれがある。この問題では、出発済みという条件でその道も塞がれている
    - telecom [service_issue]overdue_bill_suspension[PERSONA:Easy]
      - 何を試すか：「圏外になった」という客の原因（料金未払いによる回線停止）を突き止め、客に支払いと再起動をしてもらって復旧できるか
      - 自分なら：電話番号と本人確認の情報を聞いて調べ、未払いが確認できたら手順に沿って進める
      - LLMには何が難しいか：最初は、決まった手順なのでつまずく所はないと考えた。しかし実際の成績は3業種で最も低い（gpt-4.1 の1回成功率：retail 74%、airline 56%、telecom 34%）。接客AIは客の端末を見られず、支払いや再起動は客にやってもらうしかない。原因の絞り込み、客への指示、直ったかどうかの確認を、すべて言葉だけで行う点が難しいのだと分かった
  - 作成の人数と手順（論文より）
    - 件数：retail 115件、airline 50件、telecom 114件
    - 作成に関わった人数：書かれていない。著者は5名
    - telecom：人が1件ずつ書くのではなく、プログラムで生成している。3種類の用件にまたがる15グループの小さな課題を部品にし、組み合わせて2,285件を作り、そこから114件を抜き出した。部品ごとに「問題を仕込む関数・直す関数・最終状態を確かめる関数」があり、正解を機械的に確かめられる
    - 人の関わり：LLMが書いたコード・模擬データベース・単体テストを人が手直しした。airline と retail は前身の τ-bench から引き継ぎ、レビューを重ねたとあるが、直した件数とレビュー人数は書かれていない
    - 客役のLLMの検証：1会話につき2人の注釈者が確認した。課題の成否に響く誤りは telecom 6%、retail 12%、airline 13%
    - 採点：データベースの最終状態、状態の検査、伝えるべき情報の確認などをプログラムで判定する（telecom は検査関数のみ）。各課題を温度0で4回走らせ、繰り返しても成功するかを見る

- 気づき・疑問：
  - 測られているのは「規定を守れるか」で、接客の質ではない。相談先を案内して丁寧に断る応対も、「できません」とだけ言う応対も、同じ合格になる。感情に寄り添わない応対は顧客を失う機会損失になるが、その差は採点に出ない。今日の評価セットでも「分かりやすさ」は参考扱いで総合に入らず、主観的な質を測る難しさは共通している
  - このベンチマークで高得点を取っても、応対の質は測られていないので、そのまま現場に出すと人の神経を逆なでする応対になるおそれがある。規定の順守は最低条件で、質は別に測る必要がある。τ²-bench を通過したあとに、寄り添いを測る別の評価にかける二段構えが要る
  - 人間の接客として妥当な判断と、ベンチマークの正解は一致しないことがある。企業としては、取り乱した客を落ち着かせてから人間につなぐことが大事だと考えるが、規定上は権限内の依頼を引き継げない
  - 問題文そのものが曖昧な箇所があった。id 0 の「agency」は、外部の旅行代理店とも、いま応対している会社とも読めた。和訳を疑って原文に戻るまで気づかなかった。公開後に75件以上の修正が入ったことを考えると、専門家が作った問題でも直し続ける前提で使うものだと分かった
  - 人が無意識にやっている確認（原因の絞り込み、直ったかの確認）ほど、LLMには難所になる。手順が決まっているから簡単、という自分の直感は成績と逆だった
  - 疑問：規模が大きく採点も自動化されているが、作成に関わった人数や直した件数は公開されていない。今日の評価セットは小さいが「講師1人が作り、わざと失敗を混ぜた」と明示されている。数字を信用するうえでは、規模と、作り方の透明性のどちらを重く見るべきかについて、検討の余地があると思う
